# Contributing a Pattern

## What makes a good pattern

A pattern is a tactic that works in practice for working with coding agents. Not a feature request, not a tool recommendation.

Each entry must include:

1. **The pattern** - what to do, concretely
2. **Why it matters** - the failure mode it addresses
3. **Examples** - concrete situations where it applies
4. **When NOT to use** - boundaries
5. **Variations** - related approaches

## Submission

1. Add a file in `patterns/`
2. Add a row to README.md (in the right section)
3. Open a PR

PR title: `add pattern: name` or `update pattern: name`

## What gets rejected

- Generic productivity advice
- Tool-specific tips that don't apply across agents
- Patterns without concrete examples
- Patterns where "when to use" is "always"
- Aspirational patterns that haven't been used
